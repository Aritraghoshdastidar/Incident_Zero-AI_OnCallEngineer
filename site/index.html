    Why it ignored the loudest error

    On the first blind test the agent blamed an error that fired 19 times and missed the real fault, which fired twice. The loud one was background noise that was there before anything broke. Counting is not the same as noticing.

    The agent now compares each error against the minutes before the incident. Errors that were already there are marked as old and ranked last. Sort the same recorded evidence both ways.

    Try to trick it

    The model can be fooled by text hidden in a log line. So it never gets to run anything. It can only name a runbook and its settings, and a plain program checks that against a fixed list.

    Pretend the model was fooled and proposed something. Send it to the same rules the agent uses and see what happens. The rules here are a copy of the real ones in the Python code.

      Run it yourself

      You need Docker Desktop, Python 3.11 or newer, and a free Gemini API key.

      # 1. start the shop with its monitoring stack
git clone https://github.com/open-telemetry/opentelemetry-demo otel-demo
cd otel-demo
docker compose -f compose.yaml -f compose.full.yaml -f compose.observability.yaml -f compose.extras.yaml up -d
cd ..

# 2. install the agent
python -m venv .venv
.venv/Scripts/pip install -e ".[dev]"
echo GEMINI_API_KEY=your-key > .env

# 3. check it, then break something
.venv/Scripts/python -m pytest
.venv/Scripts/python -m tools.flagctl set paymentFailure 100%
.venv/Scripts/python -m uvicorn ui.app:app --port 8765      # approvals appear here
.venv/Scripts/python -m agent.run "Customers cannot complete payment at checkout" --dashboard

      Everything on this page comes from recorded runs on one laptop with a free-tier language model, built . The samples are small. The full tables, the method and the failures are in docs/RESULTS.md.
